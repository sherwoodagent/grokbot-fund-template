# Routines (create disabled; the bot enables them)

| Name | Schedule | Prompt |
|---|---|---|
| desk-pulse | Weekdays 08:00 owner local time | "If setup isn't done, stay silent. **First, data:** `/sources` needs no login (CLI 0.100.2+; if `sherwood --version` is older, tell the owner to upgrade). Then pull `sources get calendar`, `prices`, `liquidity` and `morpho`. If a feed errors, use the no-sources fallback (`propose` step 1: Chainlink feed ages read directly, no liquidity or Morpho picks) and tell the owner the first time (log it in `journal.md` so you don't repeat it). If no proposal is open and something is worth drafting, run the `propose` skill up to the owner-yes step. Message only if there's a draft or a decision. Otherwise stay silent." |
| proposal-watch | Every 10 minutes while the proposal is Pending or in GuardianReview (the review is 30 min on 4663), hourly after that; enabled only while a proposal is open | "**First, data** the same way as desk-pulse (`/sources` if the login works; re-login only when `auto_refresh` is false or on a 401 after its refresh; on a 403 or no access, the no-sources fallback in `propose` step 1). Then run the `watch` skill. Message only on a state change or a needed decision. Disable yourself when the proposal is terminal." |
| position-<id> | From `plan.md`; default weekdays twice (e.g. 09:00 and 14:30 owner local time). Created after execute, one per executed proposal | "Read `workspace/proposals/<id>/plan.md` and check each trigger and risk level with read-only commands (`sherwood proposal show`, the strategy's own reads, `sources get prices` / `calendar`, or the Chainlink feed ages directly without `/sources`). Stay silent unless a rule trips, a check can't run (stale data, blocked window), or a settle reminder is due: send the reminders the plan sets before the target settle window. When a rule trips, tell the owner the number, the rule and the action the plan suggests, then wait. **Never rebalance, adjust or settle without the owner's yes in chat for that action.** If the proposal is Settled, or its duration has ended (nothing settles by itself, so remind the owner to settle and stop the trigger checks), delete yourself once it is Settled or the owner says to stop." |

**The weekly re-login needs a signer that can sign without a human.** A sign-only wallet re-logs in with the two-step about once a week. If the agent wallet asks a person to approve each signature, the routine can't log in on its own: it messages the owner with the message to sign and waits, instead of guessing or skipping the re-login. A routine may pay for research within the owner-set daily budget (`research.daily_budget_usd`); beyond it, it messages the owner instead of paying (`research-byok`).
