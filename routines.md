# Routines (create disabled; the bot enables them)

| Name | Schedule | Prompt |
|---|---|---|
| desk-pulse | Weekdays 08:00 owner local time | "If setup isn't done, stay silent. **First, data:** `/sources` needs no login (desk minimum CLI 0.102.0; if `sherwood --version` is older, tell the owner to upgrade). Then pull `sources get calendar`, `prices`, `liquidity` and `morpho`. If a feed errors, use the no-sources fallback (`propose` step 1: Chainlink feed ages read directly, no liquidity or Morpho picks) and tell the owner the first time (log it in `journal.md` so you don't repeat it). If `journal.md` has `reclaim-bond after` a time that chain time has passed, ask the owner to reclaim that bond (`watch` step 8) before drafting. If no proposal is open and something is worth drafting, run the `propose` skill up to the owner-yes step. If nothing is worth a real draft and the vault holds idle USDG, offer the MorphoSupply satellite (`propose` → Idle vault). Message only if there's a draft or a decision. Otherwise stay silent." |
| proposal-watch | Every 10 minutes while the proposal is Pending or in GuardianReview (the review is 30 min on 4663), hourly after that; enabled only while a proposal is open | "**First, data** the same way as desk-pulse (`/sources` needs no login; desk minimum CLI 0.102.0). Then run the `watch` skill, including `sherwood guardian review` once the proposal is in GuardianReview. Message only on a state change or a needed decision. On Settled, write the `reclaim-bond after` time (`watch` step 8) and disable yourself. The bond reclaim itself waits for desk-pulse." |
| position-<id> | From `plan.md`; default weekdays twice (e.g. 09:00 and 14:30 owner local time). Created after execute, one per executed proposal | "Read `workspace/proposals/<id>/plan.md` and check each trigger and risk level with read-only commands (`sherwood proposal show`, the strategy's own reads, `sources get prices` / `calendar`, or the Chainlink feed ages directly without `/sources`). Stay silent unless a rule trips, a check can't run (stale data, blocked window), or a settle reminder is due: send the reminders the plan sets before the target settle window. When a rule trips, tell the owner the number, the rule and the action the plan suggests, then wait. **Never rebalance, adjust or settle without the owner's yes in chat for that action.** If the proposal is Settled, or its duration has ended (nothing settles by itself, so remind the owner to settle and stop the trigger checks), delete yourself once it is Settled or the owner says to stop." |

`/sources` needs no login and no weekly re-login (desk minimum CLI 0.102.0). A routine may pay for research within the owner-set daily budget (`research.daily_budget_usd`); beyond it, it messages the owner instead of paying (`research-byok`).
